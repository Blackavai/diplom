# Инструкции для Codex

## 1. Общие правила

- Общайся с пользователем на русском языке.
- Перед выполнением задачи изучай связанный код.
- Не изменяй файлы, не относящиеся к задаче.
- Сохраняй существующую архитектуру, если нет
  обоснованной причины её менять.
- Предпочитай простые и понятные решения.
- Не добавляй новые библиотеки без необходимости.
- Не удаляй работающие функции без согласования.
- Не выполняй массовый рефакторинг без разрешения.
- Если задача сформулирована как анализ,
  не изменяй исходный код.

## 2. Информация о проекте

Проект представляет собой веб-приложение.

Frontend:
- React
- Vite
- Tailwind CSS
- Axios

Backend:
- Node.js
- Express
- REST API
- JWT-авторизация (проверить реализацию)

Database:
- PostgreSQL 17

Инфраструктура:
- Docker
- Docker Compose
- Nginx

Перед работой изучай:
- docs/PROJECT_CONTEXT.md
- docs/ROADMAP.md

Не считай документацию безусловно актуальной.
При расхождении ориентируйся на реальный код.

## 3. Работа с Docker

- Используй существующую Docker-инфраструктуру.
- Не устанавливай PostgreSQL локально.
- Не изменяй production-конфигурацию без согласования.
- Не удаляй Docker volumes.
- Не выполняй docker compose down -v.
- Не очищай и не пересоздавай базу данных.
- Не запускай миграции с потерей данных.
- Перед опасными операциями запрашивай разрешение.

## 4. Frontend

- Сохраняй существующие React-компоненты.
- Используй существующий подход к стилям.
- Не изменяй дизайн без необходимости.
- Не вводи новые способы управления состоянием,
  если достаточно существующих.
- Не прописывай новые адреса API напрямую.
- Проверяй состояния загрузки и обработки ошибок.

## 5. Backend

- Сохраняй существующие маршруты API.
- Проверяй совместимость с frontend.
- Проверяй обработку ошибок.
- Проверяй валидацию входящих данных.
- Проверяй авторизацию и права доступа.
- Не раскрывай JWT_SECRET и другие секреты.
- Не изменяй структуру БД без согласования.

## 6. Проверка изменений

После изменения кода:
- Проверь синтаксис и доступные проверки.
- При необходимости проверь Docker-логи.
- Проверь совместимость frontend и backend.
- Не утверждай, что тесты пройдены,
  если фактически они не запускались.
- Не исправляй посторонние ошибки без согласования.

## 7. Работа с Git

- Не выполняй git push без разрешения.
- Не создавай коммиты без запроса.
- Не выполняй git reset --hard.
- Не удаляй пользовательские изменения.
- Перед масштабными изменениями предложи
  создать отдельную ветку.
- Не добавляй .env, пароли или секреты в Git.

## 8. Документация

После согласованных существенных изменений:
- Обновляй docs/PROJECT_CONTEXT.md при
  изменении архитектуры.
- Обновляй docs/ROADMAP.md при завершении задач.
- Обновляй docs/AUDIT.md при исправлении
  ранее выявленных проблем.

Не добавляй в документацию неподтверждённые факты.

## 9. Формат ответа

При анализе:
1. Что было изучено.
2. Что обнаружено.
3. Насколько серьёзны проблемы.
4. Какие исправления предлагаются.
5. Какие есть риски.

После изменений:
1. Какие файлы изменены.
2. Что конкретно сделано.
3. Какие проверки выполнены.
4. Какие проблемы остались.
